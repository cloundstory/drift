เรามี port อยู่แล้วสองในสาม

ในโค้ดวันนี้ me = {name, lat, lng, place} — ตัวตนที่มีชื่อและมีตำแหน่งจริงบนลูกโลก บวกกับกล่องเข้า-ออกที่แยกกันด้วย dir และการเตือนเมื่อจดหมายถึง

สิ่งที่ขาดมีสองอย่างเท่านั้น: ที่อยู่ที่คนอื่นเขียนถึงได้ กับ กุญแจ

ที่อยู่คือ port ส่วนพิกัดเป็นแค่ตัวกำหนดการเดินทาง

หนึ่ง port = หนึ่งคน ไม่ใช่หนึ่งเครื่อง เพราะบัญชีเป็นตัวยึด เปิดจากคอมหรือมือถือก็คนเดียวกัน · ย้ายที่อยู่ได้ด้วยการเรียก GPS ใหม่

แล้วจดหมายที่กำลังบินอยู่ตอนย้ายบ้านจะไปไหน — จดหมายจ่าหน้าถึง port ไม่ได้จ่าหน้าถึงพิกัด พิกัดถูกใช้ครั้งเดียวตอนส่งเพื่อคำนวณเส้นทาง ลม และเวลา แล้วค่าเหล่านั้นถูกแช่ไว้

ย้ายบ้านกลางทางจึงไม่ทำให้จดหมายหลง มันยังถึง port เดิมของคุณเสมอ เพียงแต่เดินทางมาตาม ถนนเส้นเก่า — ออกเดินทางไปหาที่ที่คุณเคยอยู่ แล้วมาถึงมือคุณที่ที่ใหม่ ไม่ต้องสร้างกลไกใหม่แม้แต่ชิ้นเดียว และเป็นเรื่องเล่าที่จริงในตัวมันเอง

ห้าจังหวะของผู้ใช้

  1. เปิด portใหม่

    ตั้งชื่อ ปักหมุดที่ที่ตัวเองอยู่ ได้ที่อยู่หนึ่งอันกลับมา — ปักหมุดมีอยู่แล้วในหน้า “คลัง”

  2. ให้ที่อยู่ใหม่

    ส่งให้คนที่อยากติดต่อ ครั้งเดียว ไม่ใช่ทุกฉบับ — นี่คือจุดที่ความสะดวกเปลี่ยนไปทั้งหมด

  3. เขียนมีแล้ว

    เลือกจากรายชื่อ port ที่รู้จัก ไม่ต้องพิมพ์เมืองปลายทางอีกต่อไป เพราะ port รู้ว่าตัวเองอยู่ไหน — ปลายทางจึงเป็น คน ไม่ใช่เมืองที่ผู้ส่งเดาเอง

  4. ปล่อยมีแล้ว

    จดหมายเดินทางด้วยลมจริงจาก port หนึ่งไปอีก port — กลไก ภาพ เวลา อากาศ ทั้งหมดไม่เปลี่ยนสักอย่าง

  5. ถึงใหม่

    จดหมายไปนอนอยู่ในกล่องของผู้รับ เปิดเมื่อไหร่ก็ได้ ไม่ต้องมีใครยื่นลิงก์ให้

สิ่งที่ port ปลดล็อก ซึ่งวันนี้เป็นไปไม่ได้เลย

  • ตอบกลับ — วันนี้ผู้รับตอบกลับไม่ได้ ต้องไปขอที่อยู่กันใหม่ พอมี port จดหมายกลายเป็นการโต้ตอบจริง ซึ่งเป็นหัวใจของคำว่าจดหมาย
  • รู้ว่าฟ้าที่เขาเป็นยังไง — port มีพิกัด เราดึงอากาศอยู่แล้ว เปิดแอปแล้วเห็นได้เลยว่าตอนนี้ฝนตกที่ port ของเพื่อนหรือเปล่า โดยไม่ต้องขอข้อมูลเพิ่มสักช่อง
  • ลมระหว่างสอง port — บาง port ฤดูนี้ลมส่ง บาง port ลมต้าน ความสัมพันธ์ระหว่างคนสองคนมี สภาพอากาศของมันเอง ที่เปลี่ยนไปตามฤดู
  • จดหมายกำลังมา — รู้ล่วงหน้าว่ามีฉบับหนึ่งกำลังเดินทางมาหา และเหลืออีกกี่ชั่วโมง ซึ่งคือการรอที่แอปนี้ตั้งใจให้เกิดตั้งแต่แรก

สิ่งที่ต้องยอมแลก

  • เซิร์ฟเวอร์ต้องถือจดหมายจริง เลี่ยงไม่ได้ ผู้รับไม่ได้ออนไลน์ตอนส่ง และไม่มีลิงก์ส่งมือต่อมืออีก — คำที่ซื่อสัตย์ที่สุดที่พูดได้คือ “เราเก็บสิ่งที่เราอ่านไม่ออก” ไม่ใช่ “เราไม่เก็บอะไรเลย”
  • กุญแจต้องกู้คืนได้ — ข้อนี้ฆ่าโปรเจกต์ได้ ถ้ากุญแจอยู่แค่ในเบราว์เซอร์ กฎ 7 วันของซาฟารีจะลบมันทิ้ง แล้วจดหมายทุกฉบับที่คนนั้นเคยได้รับ และฉบับที่กำลังจะมาถึง จะเปิดไม่ได้ตลอดกาล
  • กล่องจดหมายมาพร้อมสแปม พอมีที่อยู่ ใครก็เขียนถึงเราได้ ทางแก้ที่ตรงกับคอนเซปที่สุดคือที่อยู่ต้องเดาไม่ได้และไม่มีสมุดรายชื่อ — ให้กันเองเท่านั้น เหมือนวันนี้ แต่ให้ครั้งเดียว
  • drift หยุดเป็นไฟล์ HTML ไฟล์เดียว วันนี้เปิดจาก file:// ก็ใช้ได้ พอมี port ต้องมีโดเมน มีการ deploy มีระบบบัญชี — ข้ามไปขั้นสุดท้ายของบันไดเทคโนโลยีเลย

กฎข้อเดียวที่ทำให้ทุกอย่างลงตัว

กอล์ฟสังเกตจาก slowly ว่า จดหมายไม่เคยหาย แม้คนที่เคยคุยด้วยจะลบบัญชีไปแล้ว — สิ่งที่พฤติกรรมนั้นบอกคือกฎข้อเดียว

กฎ

จดหมายที่ส่งแล้ว เป็นของผู้รับด้วย ไม่ใช่ของผู้ส่งฝ่ายเดียว

เหมือนจดหมายกระดาษที่หย่อนตู้ไปแล้ว — คุณเผาสำเนาของตัวเองได้ แต่เอื้อมไปหยิบจากบ้านคนอื่นไม่ได้ ลบบัญชี = ลบตัวตนและกล่องของคุณ ไม่ใช่ลบความทรงจำของอีกฝ่าย

กฎนี้แก้ปัญหาที่ค้างอยู่หลายข้อพร้อมกัน แต่ มันคือข้อจำกัดสิทธิ์ในการขอลบข้อมูล จึงต้องเขียนไว้ให้ชัดตั้งแต่ตอนเปิด port ไม่ใช่ไปโผล่ในหน้านโยบายที่ไม่มีใครอ่าน

ตัดสินแล้ว — ห้ามใครอ่านจดหมายของคนอื่น แม้แต่เรา

แก้ที่ผมเขียนเกินไป

ผมเคยเขียนว่า “จดหมายไม่มีวันหาย” กับ “เราอ่านไม่ออกเลย” เลือกได้อย่างเดียว — ไม่จริง และมันเกือบทำให้ตัดสินใจผิด

สิ่งที่เห็นใน slowly คือจดหมายไม่หายแม้อีกฝ่ายลบบัญชี ข้อนั้น เข้ากับการเข้ารหัสปลายทางถึงปลายทางได้สนิท เพราะจดหมายในกล่องคุณถูกเข้ารหัสด้วยกุญแจของ คุณ ไม่ใช่ของผู้ส่ง — อีกฝ่ายลบบัญชี กุญแจของเขาหาย แต่ของคุณไม่กระทบเลย

ที่ขัดกันจริงมีข้อเดียว: ถ้าคุณลืมรหัสของตัวเอง เราช่วยไม่ได้จริง ๆ ซึ่งแคบกว่าที่ผมเขียนไว้มาก และยอมรับได้ถ้าบอกตั้งแต่ตอนสมัคร

โครงที่ต้องเป็น

  • port หนึ่งอันมีคู่กุญแจ · กุญแจสาธารณะเผยแพร่ที่ที่อยู่ port ผู้ส่งดึงไปใช้เข้ารหัส
  • กุญแจส่วนตัวถูกห่อด้วยรหัสผ่านของเจ้าของ แล้วเก็บก้อนที่ห่อแล้วไว้บนเซิร์ฟเวอร์เพื่อใช้ข้ามเครื่อง — เราถือก้อนนั้นได้ แต่เปิดไม่ออก
  • passkey เป็นของเสริม ไม่ใช่ของหลัก — ตรวจแล้วส่วนขยายที่ใช้ดึงกุญแจจาก passkey รองรับดีบนแอนดรอยด์ แต่ซาฟารียังไม่สม่ำเสมอ จึงใช้เป็นทางลัดให้เครื่องที่รองรับ ไม่ใช่ทางเดียว

ขอบเขตที่ซื่อสัตย์ — สิ่งที่เรายังเห็น แม้อ่านจดหมายไม่ได้

จุดที่ต้องขอความยินยอม

ต้องยอมก่อนถึงจะเปิด port ได้

  • จดหมายถูกเก็บไว้บนเซิร์ฟเวอร์ของเรา ในรูปที่เราเปิดไม่ออก
  • ลืมรหัสผ่านแล้วเราช่วยกู้จดหมายไม่ได้ เพราะเราไม่มีกุญแจ — ข้อนี้ต้องเห็นชัดตอนสมัคร ไม่ใช่ตัวเล็กท้ายหน้า
  • ตำแหน่งโดยประมาณจะถูกเปิดเผยต่อคนที่คุณให้ที่อยู่ — เลี่ยงไม่ได้ เพราะระยะทางคือกลไกทั้งหมดของแอป ต้องบอกก่อน ไม่ใช่ให้เขามารู้ทีหลัง
  • จดหมายที่ส่งไปแล้วจะยังอยู่ในกล่องของผู้รับ แม้คุณลบบัญชี
  • อีเมลใช้เพื่อกู้บัญชีเท่านั้น

ขอแยก ไม่ยอมก็ยังใช้งานได้

  • ขอตำแหน่งจากเครื่อง — ไม่ให้ก็พิมพ์ชื่อเมืองเองได้ ต้องไม่บังคับ
  • การแจ้งเตือนเมื่อจดหมายถึง

ต้องบอกให้รู้ แม้ไม่ต้องกดยอมรับ

  • พิกัดโดยประมาณถูกส่งออกไปยัง Open-Meteo เพื่อขอข้อมูลอากาศ — เป็นบุคคลที่สาม และวันนี้แอป ยังไม่เคยบอกใครเลย
  • ตอนกดลบบัญชี ต้องบอกให้ชัดก่อนยืนยันว่าอะไรหาย อะไรอยู่ต่อ

ข้อจำกัดสิทธิ์ขอลบข้อมูลเป็นจุดที่ต้องให้คนที่รู้กฎหมายจริงตรวจก่อนเปิดใช้ ผมเขียนได้แค่ว่าต้องมีคำตอบเรื่องอะไรบ้าง

สองเรื่องที่แก้ไปแล้ววันนี้ ไม่ต้องรอ port

  • ปัดพิกัดเหลือระดับอำเภอแล้ว — ของเดิม getCurrentPosition เก็บค่าเต็มดิบ ๆ แล้วปัดที่ทศนิยม 4 ตำแหน่งตอนแพ็กลิงก์ = ระดับ 11 เมตร ตอนนี้ปัดที่ทศนิยม 1 ตำแหน่ง = ตาราง 11.12 กม. และ ปัดตรงประตูทางเข้าทุกบาน ค่าเต็มจึงไม่เคยถูกเก็บหรือถูกส่งออก · พิกัดเดิมที่ค้างในเครื่องถูกเขียนทับแล้ว · วัดผลกระทบต่อระยะทางจริง 0.14%
  • เพิ่มหัวข้อ “อะไรออกจากเครื่องนี้บ้าง” แล้ว — บอกตรง ๆ ว่าพิกัดหยาบกับคำค้นสถานที่ถูกส่งไปยัง Open-Meteo และ เนื้อจดหมายไม่เคยออกไปไหนเลย
หลักประจำโปรเจกต์ตั้งแต่นี้ไป

ทุกครั้งที่เพิ่มการเรียกใช้บริการภายนอก ขอสิทธิ์จากเบราว์เซอร์ หรือส่งข้อมูลใด ๆ ออกจากเครื่อง ต้องเพิ่มบรรทัดเปิดเผยพร้อมกันในคอมมิตเดียวกัน ไม่ใช่ตามไปเก็บทีหลัง
